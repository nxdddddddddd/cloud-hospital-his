# 队友启动指南（拉取代码后必读）

> 适用：已经 clone 过项目、或第一次在别的电脑上运行本项目的队友。
> 目的：避免因为**数据库结构过期**导致后端启动失败。
> 最近一次数据库结构变更：`employee` 表删除 `password`、新增 `sys_user_id`（提交 `58d9716`）。

## 1. 先判断你的数据库要不要重建

**这是最容易踩坑的一步。** 拉取新代码后，如果你的数据库是旧的，后端会直接启动失败。

打开 MySQL 客户端，执行：

```sql
USE his_cloud_completed;
SHOW COLUMNS FROM employee LIKE 'sys_user_id';
```

| 结果 | 说明 | 该做什么 |
|---|---|---|
| 查到一行 `sys_user_id` | 数据库是新的 | 跳到第 5 节启动 |
| 查不到（Empty set） | 数据库是旧的 | 按第 3 节重建 |
| 报 `Table 'employee' doesn't exist` | 根本没导过库 | 按第 2 节全新初始化 |

> 不要凭感觉判断。`employee` 表里现在**没有** `password` 字段了，如果你还记得见过它，说明库是旧的。

## 2. 全新环境：从零初始化

### 2.1 环境要求

| 软件 | 版本 | 说明 |
|---|---|---|
| JDK | 17 | 后端编译运行 |
| Maven | 3.9+ | 或用 IDEA 自带 |
| Node.js | 20+ | 前端构建 |
| MySQL | 8.0.16+ | 需要支持 `CHECK` 约束 |
| Redis | 任意较新版本 | 存登录令牌和验证码，**必须启动** |

### 2.2 导入数据库

进入项目的 `sql` 目录：

```text
cd sql
mysql -u root -p
```

如果提示 `mysql` 不是命令，用完整路径，例如：

```text
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p
```

登录后**按顺序逐行执行**，顺序不能乱：

```sql
source his_cloud.sql
USE his_cloud_completed;
source ruoyi_system.sql
source quartz.sql
source his_demo_data.sql
```

四份脚本的作用：

| 脚本 | 作用 |
|---|---|
| `his_cloud.sql` | 建库 + 22 张 HIS 业务表 |
| `ruoyi_system.sql` | RuoYi 权限表、菜单、日志，末尾补员工账号外键 |
| `quartz.sql` | 定时任务表 |
| `his_demo_data.sql` | 演示账号、科室医生、药品库存、虚构患者（可重复执行） |

### 2.3 检查导入结果

```sql
USE his_cloud_completed;
SHOW TABLES;
```

应显示 **53 张表**。再确认关键字段：

```sql
SHOW COLUMNS FROM employee LIKE 'sys_user_id';
```

必须能查到。

## 3. 已有旧库：安全重建

> ⚠️ 重建会清空 `his_cloud_completed` 里的数据。如果你有自己录入的测试数据，先备份。

### 3.1 备份（可选但建议）

在命令行执行，不要进 `mysql>` 交互界面：

```text
mysqldump -u root -p his_cloud_completed > his_backup.sql
```

### 3.2 重建

```sql
DROP DATABASE IF EXISTS his_cloud_completed;
```

然后**按第 2.2 节的顺序重新执行四份脚本**。

旧库里如果有 `employee.password`，重建后就没了，这是预期结果，不要手动加回去。

## 4. 启动 Redis

后端登录依赖 Redis，没启动会报连接失败。

```text
redis-server
```

Windows 也可以用 `net start Redis`，或用 Docker：

```text
docker run -d -p 6379:6379 redis
```

验证：

```text
redis-cli ping
```

返回 `PONG` 即可。

## 5. 启动后端

### 5.1 数据库账号不是 root/password 时

后端默认读 `root/password`。你的密码不同就必须设置环境变量，**否则报 `Access denied`**。

在 IDEA 的 `RuoYiApplication` 运行配置里，Environment variables 填入：

```text
HIS_DB_USERNAME=root;HIS_DB_PASSWORD=你的密码
```

命令行方式（PowerShell）：

```powershell
$env:HIS_DB_USERNAME='root'
$env:HIS_DB_PASSWORD='你的密码'
```

### 5.2 用 IDEA 启动

打开 `backend/ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java`，点运行。

### 5.3 用命令行启动

首次先安装依赖：

```text
cd backend
mvn install -DskipTests
```

然后启动：

```text
cd ruoyi-admin
mvn spring-boot:run
```

看到 `Started RuoYiApplication` 即成功，地址 `http://localhost:8080`。

### 5.4 上传目录

配置里 `ruoyi.profile` 默认是 `D:/cloud-hospital-his/uploadPath`。如果这个目录不存在且你要用文件上传，先手动创建，或设置：

```text
HIS_PROFILE=你的目录
```

不涉及上传功能时可以先不管。

## 6. 启动前端

```text
cd frontend
```

首次需要把环境文件复制一份：

```powershell
Copy-Item .env.example .env.development
```

然后安装依赖并启动：

```text
npm install
npm run dev
```

打开终端提示的地址（通常是 `http://localhost:5173`）。

### 关于 `VITE_USE_MOCK_AUTH`

`.env.example` 里默认是：

```text
VITE_USE_MOCK_AUTH=true
```

| 值 | 效果 |
|---|---|
| `true` | 前端用模拟登录，**不需要后端**，可以单独调页面 |
| `false` | 连接真实后端，用数据库里的账号登录 |

只做页面样式时保持 `true`；要联调接口改成 `false` 后**重启前端**（改环境变量必须重启，热更新不生效）。

## 8. 常见报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `Unknown column 'sys_user_id' in 'field list'` | 数据库是旧的 | 按第 3 节重建 |
| `Field 'password' doesn't have a default value` | 数据库是旧的 | 同上 |
| `Table 'his_cloud_completed.sys_user' doesn't exist` | 没导 `ruoyi_system.sql` | 补导，注意先 `USE` 库 |
| `Table 'his_cloud_completed.employee' doesn't exist` | 没导 `his_cloud.sql` | 按顺序重导 |
| `Access denied for user 'root'@'localhost'` | 数据库密码不对 | 设 `HIS_DB_PASSWORD` |
| `Unable to connect to Redis` | Redis 没启动 | 按第 4 节启动 |
| `Port 8080 was already in use` | 端口被占 | 关掉旧进程，或改 `server.port` |
| 登录提示密码错误 | 账号来自演示脚本，密码是 `admin123` | 确认执行过 `his_demo_data.sql` |
| 页面能开但接口 401 | 前端连了后端但没登录 | 检查 `VITE_USE_MOCK_AUTH=false` 后是否重新登录 |
| 中文显示成问号 | 客户端编码不对 | 导入时加 `--default-character-set=utf8mb4` |

三项都通过再 `git push`。
