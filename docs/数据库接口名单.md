# 云医院 HIS 数据库接口名单

> 适用：成员一（挂号收费、药房）、成员二（门诊医生）、成员三（检查、检验、处置）
> 基线：`docs/需求规格说明书.md`、`sql/his_cloud.sql`、当前 `main` 分支代码
> 用途：统一前后端字段、状态值和数据归属，避免三人并行开发时接口对不上或互相覆盖。

## 1. 通用约定

### 1.1 路径与认证

- 业务接口统一前缀 `/his`，前端通过 `VITE_APP_BASE_API` 代理到 `http://localhost:8080`。
- 认证沿用 RuoYi：请求头 `Authorization: Bearer <token>`，由 `frontend/src/api/request.ts` 统一注入。
- 分页参数统一 `pageNum`、`pageSize`；排序参数 `orderByColumn`、`isAsc`。

### 1.2 响应结构

单对象返回 `AjaxResult`：

```json
{ "code": 200, "msg": "操作成功", "data": { } }
```

分页列表返回 `TableDataInfo`：

```json
{ "code": 200, "msg": "查询成功", "rows": [], "total": 0 }
```

失败时 `code` 为 500，`msg` 为可直接展示的中文原因；未登录或令牌失效返回 HTTP 401。前端拦截器已按此实现，**不要另造响应格式**。

### 1.3 金额、数量与时间

| 类型 | 约定 |
|---|---|
| 金额 | `DECIMAL(12,2)`，后端计算，前端只展示，不提交金额 |
| 药品数量 | `DECIMAL(12,3)` |
| 日期时间 | 字符串 `yyyy-MM-dd HH:mm:ss`；挂号日期 `visit_date` 只存当日 `00:00:00` |
| 主键 | `BIGINT`，前端按字符串或数字均可，禁止用浮点比较 |

### 1.4 状态枚举（前后端必须一致）

| 业务 | 数据库值 | 前端值 | 含义 |
|---|---|---|---|
| 挂号 `visit_state` | `1` | `waiting` | 已挂号，待接诊 |
| | `2` | `visiting` | 医生已接诊 |
| | `3` | `finished` | 看诊结束 |
| | `4` | `cancelled` | 已退号 |
| 医技 `*_state` | `UNPAID` | `unpaid` | 已开立未缴费 |
| | `PAID` | `pending` | 已缴费待执行 |
| | `EXECUTING` | `inProgress` | 执行中 |
| | `COMPLETED` | `completed` | 已完成 |
| | `CANCELLED` | `cancelled` | 已作废 |
| | `REFUNDED` | `refunded` | 已退费 |
| 处方 `drug_state` | `UNPAID` / `PAID` / `DISPENSED` / `RETURNED` / `REFUNDED` / `CANCELLED` | 同名小写 | 未缴费 / 待发药 / 已发药 / 已退药 / 已退费 / 已作废 |
| 收费单 `status` | `PAID` / `PARTIAL_REFUNDED` / `REFUNDED` | 同名小写 | 已收费 / 部分退费 / 全额退费 |

医技模块前端已有映射函数 `mapMedicalTechApiOrder`，新增模块请复用同一套映射，不要各自转换。

### 1.5 接口实现状态

| 状态 | 说明 |
|---|---|
| ✅ 已实现 | `main` 已有 Controller / Service / Mapper |
| 🚧 待实现 | 仅有页面或原型，需要对应负责人补齐 |

当前仅医技模块已实现；其余接口需按本名单补齐，**字段名以下表为准**。

### 2.2 成员一：挂号收费（8.1）

| 方法 | 路径 | 用途 | 权限 | 状态 |
|---|---|---|---|---|
| GET | `/his/registration/availableDoctors` | 按科室、日期、午别、号别查可挂号医生及剩余号额 | `his:registration:list` | 🚧 |
| GET | `/his/registration/list` | 挂号记录分页 | `his:registration:list` | 🚧 |
| GET | `/his/registration/{id}` | 挂号详情 | `his:registration:query` | 🚧 |
| POST | `/his/registration` | 窗口挂号 | `his:registration:add` | 🚧 |
| POST | `/his/registration/{id}/cancel` | 窗口退号 | `his:registration:edit` | 🚧 |
| GET | `/his/charge/pending/{registrationId}` | 查询待收费项目 | `his:charge:list` | 🚧 |
| POST | `/his/charge` | 完成门诊收费 | `his:charge:add` | 🚧 |
| GET | `/his/charge/list` | 费用记录查询 | `his:charge:list` | 🚧 |
| GET | `/his/refund/available/{registrationId}` | 查询可退费项目 | `his:charge:list` | 🚧 |
| POST | `/his/refund` | 办理退费 | `his:charge:refund` | 🚧 |

**可挂号医生** `GET /his/registration/availableDoctors`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `deptmentId` | Long | 是 | 挂号科室 |
| `visitDate` | String | 是 | `yyyy-MM-dd` |
| `noon` | String | 是 | `上午` / `下午` |
| `registLevelId` | Long | 否 | 过滤号别 |

返回数组，每项：`employeeId`、`realname`、`registLevelId`、`registLevelName`、`registFee`、`quota`、`registered`、`remaining`。
`remaining = quota - 已挂号数(visit_state in 1,2,3)`，为 0 时前端禁止选择。

**窗口挂号** `POST /his/registration`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `caseNumber` | String | 是 | 病历号，复诊沿用 |
| `realName` | String | 是 | 患者姓名 |
| `gender` | String | 否 | `男` / `女` |
| `cardNumber` | String | 否 | 身份证号 |
| `birthdate` | String | 否 | `yyyy-MM-dd` |
| `age` / `ageType` | Integer / String | 否 | 必须同时有值，`年` 或 `天` |
| `homeAddress` | String | 否 | 住址 |
| `visitDate` | String | 是 | `yyyy-MM-dd`，后端补 `00:00:00` |
| `noon` | String | 是 | `上午` / `下午` |
| `deptmentId` | Long | 是 | 科室 |
| `employeeId` | Long | 是 | 医生 |
| `registLevelId` | Long | 是 | 号别，金额取 `regist_fee` |
| `settleCategoryId` | Long | 是 | 结算类别 |
| `isBook` | String | 否 | `是` / `否`，默认 `否` |
| `registMethod` | String | 是 | `现金` / `银行卡` / `医保卡` / `微信` / `支付宝` |
| `requestKey` | String | 是 | 前端生成 UUID，防重复提交 |

返回：`{ id, caseNumber, registMoney, visitState }`。后端必须：校验号额、用 `regist_level.regist_fee` 计算 `regist_money`、写 `request_key`、同一事务内创建 `charge_order` + `charge_item` + `payment_record` 完成挂号收费。

**待收费项目** `GET /his/charge/pending/{registrationId}`

返回 `rows`，每项：`sourceType`（`REGISTER`/`CHECK`/`INSPECTION`/`DISPOSAL`/`PRESCRIPTION`）、`sourceId`、`itemName`、`quantity`、`unitPrice`、`amount`、`status`。仅返回状态为 `UNPAID` 且未在 `charge_item` 出现过的记录。

**收费** `POST /his/charge`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `registrationId` | Long | 是 | 本次挂号 |
| `sourceType` | String | 是 | 同上枚举 |
| `sourceIds` | Long[] | 是 | 本次收费的业务行 ID |
| `method` | String | 是 | 支付方式 |
| `receiptRef` | String | 是 | 收款凭据号，唯一 |
| `requestKey` | String | 是 | 幂等键 |

后端必须重新按 `unit_price × quantity` 计算金额并写 `charge_order`、`charge_item`、`payment_record`，再把来源行状态改为 `PAID`。**前端提交的金额一律忽略。**

**退费** `POST /his/refund`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `registrationId` | Long | 是 | 挂号 |
| `chargeItemIds` | Long[] | 是 | 要退的收费明细 |
| `reason` | String | 是 | 退费原因 |
| `refundRef` | String | 是 | 退款凭据号，唯一 |
| `requestKey` | String | 是 | 幂等键 |

规则：已执行（`EXECUTING`/`COMPLETED`）的医技项目、已发药（`DISPENSED`）的处方不得直接退费；`refund_item.charge_item_id` 唯一，一条明细只能退一次。

### 2.3 成员一：药房管理（8.5）

| 方法 | 路径 | 用途 | 权限 | 状态 |
|---|---|---|---|---|
| GET | `/his/pharmacy/dispensing/pending` | 待发药处方 | `his:pharmacy:list` | 🚧 |
| POST | `/his/pharmacy/dispensing/{prescriptionId}` | 确认发药 | `his:pharmacy:dispense` | 🚧 |
| GET | `/his/pharmacy/return/available` | 可退药记录 | `his:pharmacy:list` | 🚧 |
| POST | `/his/pharmacy/return/{prescriptionId}` | 确认退药 | `his:pharmacy:return` | 🚧 |
| GET | `/his/pharmacy/transactions` | 药品交易记录 | `his:pharmacy:list` | 🚧 |

**待发药** 返回：`prescriptionId`、`caseNumber`、`realName`、`drugName`、`drugFormat`、`drugNumber`、`drugUnit`、`drugUsage`、`unitPrice`、`amount`、`doctorName`、`creationTime`。条件为 `drug_state = 'PAID'`。

**发药** `POST /his/pharmacy/dispensing/{prescriptionId}`，请求体 `{ operatorId, requestKey }`。同一事务内：校验库存充足 → `drug_stock.on_hand` 扣减 → 写 `stock_movement`（`DISPENSE`，`quantity_delta` 为负）→ `prescription.drug_state = 'DISPENSED'`。

**退药** `POST /his/pharmacy/return/{prescriptionId}`，请求体 `{ operatorId, requestKey, reason }`。仅 `DISPENSED` 可退；回补库存、写 `RETURN` 流水、状态改为 `RETURNED`。**退药完成后方可走退费。**

**交易记录** 支持 `keyword`、`drugId`、`startTime`、`endTime`、`movementType`，返回 `movement_type`、`drug_name`、`quantity_delta`、`balance_after`、`operator`、`created_at`。

### 2.4 成员二：门诊医生（8.2）

| 方法 | 路径 | 用途 | 权限 | 状态 |
|---|---|---|---|---|
| GET | `/his/doctor/visits` | 待诊/已诊患者 | `his:doctor:visits` | 🚧 |
| POST | `/his/visit/{registrationId}/accept` | 接诊 | `his:doctor:accept` | 🚧 |
| GET | `/his/medicalRecord/{registrationId}` | 查询病历 | `his:doctor:visits` | 🚧 |
| PUT | `/his/medicalRecord` | 保存病历 | `his:doctor:edit` | 🚧 |
| POST | `/his/medicalOrder` | 开立检查/检验/处置申请 | `his:doctor:order` | 🚧 |
| POST | `/his/prescription` | 开立处方 | `his:doctor:order` | 🚧 |
| POST | `/his/medicalOrder/{type}/{id}/cancel` | 作废未缴费申请或处方 | `his:doctor:order` | 🚧 |
| GET | `/his/visit/{registrationId}/results` | 查看医技结果 | `his:doctor:visits` | 🚧 |
| PUT | `/his/visit/{registrationId}/diagnosis` | 保存诊断和处理意见 | `his:doctor:edit` | 🚧 |
| POST | `/his/visit/{registrationId}/complete` | 完成本次诊疗 | `his:doctor:edit` | 🚧 |
| GET | `/his/visit/{registrationId}/costs` | 本次就诊费用 | `his:doctor:visits` | 🚧 |

**待诊列表** `GET /his/doctor/visits?visitState=&keyword=&visitDate=`：`visitState` 取 `waiting`（1）或 `visiting`（2），默认返回 1 和 2。**医生身份必须取当前登录用户**，通过 `employee.sys_user_id = 当前 userId` 定位 `employee.id`，不得由前端传 `employeeId`。

**接诊** 只允许 `visit_state = 1` → `2`，并返回空病历模板。

**病历** `PUT /his/medicalRecord` 字段：`registrationId`、`readme`（主诉，必填）、`present`、`presentTreat`、`history`、`allergy`、`physique`、`proposal`、`careful`、`diagnosis`、`cure`、`diseaseIds`（数组，写 `medical_record_disease`）。一次挂号只允许一份病历（`register_id` 唯一）。

**开立申请** `POST /his/medicalOrder`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `registrationId` | Long | 是 | 挂号 |
| `techType` | String | 是 | `CHECK` / `INSPECTION` / `DISPOSAL` |
| `items` | Array | 是 | 每项 `medicalTechnologyId`、`info`（目的要求）、`position`（部位，可空） |
| `requestKey` | String | 是 | 幂等键，整批共用一个 |

后端按 `techType` 写入对应表（`check_request` / `inspection_request` / `disposal_request`），`line_no` 从 1 递增，`unit_price` 取项目当前价，状态 `UNPAID`，`created_by` 取当前医生。

**开立处方** `POST /his/prescription`：`registrationId`、`items[]`（`drugId`、`drugUsage`、`drugNumber`）、`requestKey`。写入 `prescription`，状态 `UNPAID`。

**作废** `type` 取 `check` / `inspection` / `disposal` / `prescription`，仅 `UNPAID` 可作废为 `CANCELLED`。

**完成诊疗** 仅 `visit_state = 2` → `3`，且要求病历已保存。

### 2.5 成员三：检查、检验、处置（8.3 / 8.4 / 8.6）

**以下为 `main` 已实现接口，字段以现有代码为准，其他成员请勿改动路径。**

| 方法 | 路径 | 用途 | 权限 | 状态 |
|---|---|---|---|---|
| GET | `/his/medical-tech/{category}` | 查询项目列表 | `his:{category}:list` | ✅ |
| PUT | `/his/medical-tech/{category}/{id}/start` | 登记并开始执行 | `his:{category}:edit` | ✅ |
| PUT | `/his/medical-tech/{category}/{id}/complete` | 录入结果并完成 | `his:{category}:edit` | ✅ |

`{category}` 取 `examination`（检查）、`laboratory`（检验）、`treatment`（处置）。

> 与需求文档 7.4 的差异：文档写作 `/his/execution/{type}` + `check|inspection|disposal`。**实际代码与前端统一使用 `/his/medical-tech/{category}`**，本名单以代码为准。若后续要改回文档写法，必须三人同时改前端 `api/medicalTech.ts`、路由和 Controller，不能只改一边。

**列表** 查询参数：`status`（`pending` / `inProgress` / `completed` / `all`）、`keyword`（患者姓名、病历号、项目名）。返回字段：`id`、`orderNo`、`category`、`patientName`、`outpatientNo`、`itemName`、`department`、`doctorName`、`appliedAt`、`status`、`executor`、`executedAt`、`result`。

**开始执行** 无请求体。仅 `PAID` 可执行，状态改为 `EXECUTING`。执行人和执行时间由后端从**当前登录用户**推导：`employee.sys_user_id = SecurityUtils.getUserId()`，不接受前端提交的姓名。

**完成执行** 请求体 `{ result, executedAt }`，`result` 非空，状态改为 `COMPLETED`。执行人同样取自当前登录用户。数据库 `ck_*_request_4/5` 会校验执行人和结果必填。

> 2026-11-08 变更：原接口要求前端提交 `executor` 姓名字符串，后端按姓名反查员工，存在冒用风险。现已改为登录身份推导，前端「执行人员」输入框改为只读展示。

## 3. 数据归属与冲突预防

并行开发最容易出问题的是**同一张表被多人写入**。按列划分归属：

| 表 | 成员一 | 成员二 | 成员三 |
|---|---|---|---|
| `register` | 插入挂号；`visit_state` 1→4（退号） | `visit_state` 1→2、2→3 | 只读 |
| `medical_record` / `medical_record_disease` | 只读 | 唯一写入方 | 只读 |
| `check_request` / `inspection_request` / `disposal_request` | 只改状态 `UNPAID`→`PAID`、`→REFUNDED` | 插入申请；`UNPAID`→`CANCELLED` | 执行人、执行时间、结果；`PAID`→`EXECUTING`→`COMPLETED` |
| `prescription` | 状态 `UNPAID`→`PAID`、`PAID`→`DISPENSED`、`DISPENSED`→`RETURNED`、`→REFUNDED` | 插入处方；`UNPAID`→`CANCELLED` | 只读 |
| `charge_order` / `charge_item` / `payment_record` / `refund_record` / `refund_item` | 唯一写入方 | 只读 | 只读 |
| `drug_stock` / `stock_movement` | 唯一写入方 | 只读 | 只读 |
| `department` / `employee` / `regist_level` / `scheduling` / `settle_category` / `disease` / `medical_technology` / `drug_info` | 基础数据，改字段前先登记 | 同左 | 同左 |

补充规则：

1. **状态只能单向推进**，所有更新必须带 `where 状态 = 期望旧值`，靠影响行数判断是否成功，不要先查后改。
2. **金额一律后端算**，`charge_item.amount` 有 CHECK 约束，前端传的金额不参与计算。
3. **跨表一致性由 Service 事务保证**：收费单总额与明细合计、退款额与退款明细、库存与流水，数据库 CHECK 管不了跨表，必须写在同一个 `@Transactional` 里。
4. **不要物理删除**诊疗、收费、库存记录，只用状态字段。
5. 新增字段先改 `sql/his_cloud.sql` 并在本文件登记，再改实体和前端，避免三人各改各的。

## 6. 联调顺序建议

1. **成员一**先完成挂号与收费，产出可用的 `register` 和 `PAID` 数据。
2. **成员二**依赖挂号数据，完成接诊、病历、开立申请和处方。
3. **成员三**依赖 `PAID` 的医技申请，完成执行与结果录入。
4. **成员一**再补药房发药/退药，最后三方一起验证退号、退费、退药三条逆向流程。
